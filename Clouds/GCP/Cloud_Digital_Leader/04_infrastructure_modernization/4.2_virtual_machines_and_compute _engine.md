## 4.2 — Virtual Machines and Compute Engine

### Key Concepts
Before choosing a compute approach, we need to understand the building blocks.

**What is "Compute"?**
In cloud computing, compute refers to the processing power, memory (RAM), and networking resources required to run applications and process data. Associated tasks include storing, retrieving, comparing and analyzing the information. Think of it as the "brain" or the engine of the cloud. Whenever an application runs a calculation, serves a webpage, processes a transaction, or runs an AI model, it is consuming compute resources. In a traditional data center, compute is tied to physical, on-premises servers; in the cloud, compute is virtualized and delivered as a scalable utility that we pay for by the second or millisecond.

**Virtualization**
The fundamental technology that makes cloud computing possible. It uses a specialized layer of software (called a hypervisor) to abstract and separate physical hardware resources—like CPUs, memory, and storage—into multiple independent, virtual versions. Instead of being locked into running a single operating system on a physical machine, virtualization allows one physical server to host multiple completely distinct environments/systems at the same time. These systems are called virtual machines.

**Virtual Machine (VM)**
A software-based simulation of a physical computer. Through virtualization, a single physical server can host multiple isolated VMs simultaneously. While each VM is completely isolated from the others and operates with its own dedicated operating system, CPU allocation, and memory—functioning exactly like a full-fledged operating system—they all draw from a shared underlying pool of processing, storage, and networking resources. Like renting a private office in a shared building — our office has its own lock and furniture; we don't share it with other tenants.

**Preemptible VMs or Spot VMs**
Heavily discounted virtual machines (60–91% cheaper than standard VMs) that Google may shut down with 30 seconds' notice when it needs the capacity for higher-priority workloads. Only suitable for workloads that can handle interruption — batch data processing, ML model training, video rendering, simulations.

- **Preemptible VMs (Legacy):** Had a hard **24-hour maximum runtime limit**. Even if Google didn't need the capacity back, the system would automatically shut the VM down after exactly 24 hours.
- **Spot VMs (Current):** Removed that 24-hour cap. A Spot VM will run indefinitely as long as Google Cloud has the spare capacity and doesn't need to reclaim it.

### Google Cloud Product: Compute Engine
An Infrastructure as a Service (IaaS) offering that enables users to deploy and run virtual machines on Google's infrastructure. Compute Engine provides complete flexibility over hardware specifications, allowing us to define precise machine properties—such as the number of virtual CPUs (vCPUs), the operating system, and the memory capacity—either by selecting from a diverse set of predefined machine types or by tailoring custom machine configurations to exact workload requirements.

- Best for: legacy applications that need a specific OS, custom software environments, full control over the server

**Deployment Options:** VM instances can be provisioned and managed through several interfaces depending on our workflow:

- **Google Cloud Console:** A web-based graphical interface designed for administering Google Cloud projects and resources visually.
- **Google Cloud CLI (gcloud):** A command-line interface that allows us to create and manage VMs using terminal commands (e.g., `gcloud compute instances create`) and infrastructure automation tools like **Terraform**, which allows us to define, provision, and version our VM infrastructure declaratively using configuration files.

### The Strategic Benefits of Cloud Compute
Running our compute workloads in the cloud instead of managing on-premises data centers provides several transformative advantages to an organization:

- **Elasticity and Scalability:** Cloud compute allows businesses to seamlessly scale up or down based on real-time demand via autoscaling. Organizations no longer need to pay for idle standby servers just to handle seasonal traffic spikes like Black Friday.
- **Shift from CapEx to OpEx:** Instead of massive, upfront Capital Expenditures (CapEx) purchasing physical servers and data centers, organizations transition to a predictable, pay-as-you-go Operational Expenditure (OpEx) model, freeing up capital for strategic business growth.
- **High Availability and Reliability:** Cloud compute resources run on highly redundant global networks. Built-in load balancing instantly routes traffic away from failing hardware, drastically minimizing business downtime.
- **Built-In Infrastructure Security:** Cloud compute infrastructure benefits from multi-layered physical and digital security protocols that are financially and operationally impossible for most individual businesses to duplicate. This includes custom-designed hardware chips (like Google's Titan), end-to-end data encryption by default, identity and access management, network security, and continuous, automated vulnerability patching.
- **Faster Time to Market:** Provisioning an on-premises physical server takes weeks or months for hardware delivery, setup, and configuration. In the cloud, developers can provision and launch new compute instances in seconds, enabling rapid experimentation and product deployment.
- **Reduced Operational Overhead (abstraction):** Google handles the physical hardware maintenance, infrastructure cooling, physical security, and underlying virtualization layers. This offloads routine maintenance tasks so internal IT teams can pivot to driving business innovation.

### The Business Value of Compute Engine
Compute Engine lets organizations run virtual machines on Google's global infrastructure. Business value:

- **Immediate migration path** — existing applications (SAP, Oracle, Windows Server applications, legacy Java systems) can be moved as VMs with minimal or no code changes
- **Pay by the second** — start and stop VMs as needed (pay-as-you-go model); no wasted capacity
- **Right-sizing** — choose from 30+ machine configurations or create custom CPU/memory combinations to pay only for what we need
- **Global reach** — launch VMs in 40+ regions in minutes; no hardware procurement
- **Sustained Use Discounts** — automatically receive discounts of up to 30% for VMs that run more than 25% of the month, with no commitment required

**Rehost value for legacy applications:** Many enterprises have applications (Oracle databases, SAP ERP, mainframe workloads) that cannot practically be rewritten. Rehosting these to Compute Engine VMs immediately eliminates data center costs, improves disaster recovery, and gives access to Google's network — without touching the application.
