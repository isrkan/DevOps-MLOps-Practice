## 4.8 — Hybrid and Multi-Cloud

### Why Organizations Choose Hybrid Cloud
**Hybrid cloud** combines on-premises infrastructure with public cloud (like Google Cloud), connected by a network. Organizations choose hybrid for specific, legitimate reasons:

- **Regulatory compliance** — some data legally cannot leave certain physical locations or must be stored in specific countries (patient health records under HIPAA, financial data under certain banking regulations, government data under sovereignty requirements); the regulated data stays on-premises while everything else runs in the cloud
- **Legacy systems** — some applications are deeply integrated with physical hardware or have not been validated to run in a cloud environment; these stay on-premises while newer systems move to cloud
- **Latency requirements** — certain industrial, manufacturing, or real-time financial applications require sub-millisecond response times that require processing to happen locally, at the "edge," not in a distant data center
- **Gradual migration** — a large enterprise cannot migrate everything in one year; they run on-premises and cloud in parallel for 2–5 years during the transition

---

### Why Organizations Choose Multi-Cloud
**Multi-cloud** means using two or more public cloud providers simultaneously (e.g., Google Cloud + AWS, or Google Cloud + Azure).

- **Avoid vendor lock-in** — depending on a single cloud provider creates risk; if prices rise or service quality drops, switching is costly; using multiple clouds gives negotiating leverage
- **Best-of-breed services** — Google Cloud is widely considered best for AI/ML (Vertex AI, BigQuery) and analytics; other providers may have strengths in specific areas; organizations use each for what it does best
- **Geographic requirements** — a specific cloud provider may not have a region in a country where our data must reside; a second provider fills the gap
- **Regulatory requirements** — some government contracts require certain cloud providers; multi-cloud may be mandated
- **Business continuity** — a catastrophic outage at one provider (rare but possible) can be survived if critical systems are replicated to a second provider

**Trade-offs of multi-cloud:** More complexity (different tools, different APIs, different security models, different cost structures); higher operational overhead; requires teams with skills across multiple platforms.

### GKE Enterprise — Managing Hybrid and Multi-Cloud
**The problem:** If we're running applications on-premises, on Google Cloud, and on AWS, we're dealing with three different environments, three different management tools, three different security configurations. This is complex, expensive, and error-prone.

**GKE Enterprise** (previously called Anthos) is Google's platform for managing containerized applications across any environment — on-premises, Google Cloud, AWS, or Azure — from a **single control plane**.

**What GKE Enterprise provides:**

- **Single management console** — see and manage all our Kubernetes clusters (on-premises and in any cloud) from one Google Cloud dashboard
- **Consistent security policies** — define security rules once and apply them across all environments automatically; policy violations flagged centrally
- **Consistent monitoring** — all application health metrics flow into a single view regardless of where the app is running
- **Service mesh** — manage how our services communicate and authenticate with each other across environments
- **Config management** — use Git repositories to manage the configuration of all clusters consistently (GitOps)

**Business value:**
- Reduces the operational complexity of hybrid/multi-cloud from "managing three separate environments" to "managing one environment with three locations"
- Enables a consistent security posture across all environments — no gaps where a different environment has weaker controls
- Allows a single operations team to manage infrastructure across cloud providers rather than needing separate cloud-specific specialists

> **Key Point:** GKE Enterprise is specifically about managing *containers* across environments. It uses Kubernetes as the common language. If an organization is running VMs (not containers) in multiple environments, GKE Enterprise is not the right tool.
