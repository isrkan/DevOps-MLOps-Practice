## 4.4 — Serverless Computing

### What "Serverless" Really Means
The name is slightly misleading — servers still exist. "Serverless" means *we* don't think about, provision, or manage any servers. The cloud provider handles all of that, resources like compute power are automatically provisioned in the background as needed. We focus purely on our application code or container.

**Key benefits of serverless:**

- **No infrastructure management** — no VMs to provision, no OS patches, no capacity planning
- **Automatic scaling** — the platform scales from zero requests to millions and back to zero, automatically, in seconds
- **Pay per actual use** — billed only for the compute time our code runs; a function that runs for 200ms is billed for 200ms, not for a whole hour
- **Improved resilience** — code automatically runs on infrastructure that is inherently fault-tolerant. If an underlying machine fails, the serverless platform instantly re-routes execution to healthy infrastructure without any downtime or manual intervention required.
- **Built-in high availability** — the serverless platform is distributed across multiple zones by default
- **Faster development** — developers write code, deploy, and it runs — no DevOps pipeline for infrastructure needed

**Key concepts to understand:**

* **Function:** In software engineering, a function is a small, self-contained block of code designed to perform a single, specific task (e.g., resizing an image, validating a credit card number, or updating a database row). It takes an input, processes it, and returns an output.
* **Function as a Service (FaaS):** A specific category of serverless computing that allows developers to deploy individual functions to the cloud. Instead of deploying an entire software application, we deploy just that single block of code. The cloud provider executes the function only when it is specifically triggered by an event, completely abstracting away the underlying operating system and hardware.

### Google Cloud's Serverless Products

**Cloud Run**
Runs containerized applications in a fully managed environment. We package our application into a container image, deploy it to Cloud Run, and Google handles everything else — scaling, load balancing, TLS certificates, domain management. Supports any programming language and any framework.

- Scales from 0 instances (when idle, no cost) to thousands (during peak traffic) in seconds
- Perfect for: APIs, web applications, microservices, data processing jobs
- Business example: A startup's product API serves 100 requests/day normally but gets 500,000 requests during a viral social media moment. Cloud Run scales instantly to handle the spike and back down when it's over — the company pays only for actual requests.

**Cloud Functions**
Run a single piece of code in response to a specific event — without any surrounding application framework. Each function does one thing. Events that can trigger a function include: an HTTP request, a new file uploaded to Cloud Storage, a message published to Pub/Sub, a database change in Firestore.

- Ideal for lightweight tasks, integrations, and automation
- Business example: Every time a customer uploads a PDF contract to Cloud Storage, a Cloud Function automatically extracts the text, identifies key dates using the Natural Language API, and saves a structured summary to the database — all without any server running continuously.

**App Engine**
A fully managed platform for web applications and APIs. Developers deploy application code (Python, Java, Node.js, Go, etc.) and App Engine handles runtime, scaling, load balancing, and version management. App Engine Standard (for short-lived request-response apps) and App Engine Flexible (for longer-running processes, custom runtimes) serve different needs.

- Automatic versioning: deploy version 2 of our app alongside version 1; split traffic 90%/10% to test new version before full rollout
- Business example: A company's internal reporting portal deployed on App Engine scales automatically during the morning rush (9am–10am when everyone checks dashboards) and scales down to near-zero at night.

> **Key Point:** Cloud Run, App Engine, and Cloud Functions are all "serverless" in that you manage no servers. The difference: Cloud Functions = one function triggered by one event; App Engine = a full web application; Cloud Run = a containerized application of any complexity.
