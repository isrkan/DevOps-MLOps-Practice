## Section 3.2 — Google Cloud's AI and ML Solutions

### 3.2.a — Key Decisions When Selecting an AI/ML Solution
When evaluating which Google Cloud AI product to use, four dimensions drive the decision:

#### The Four Decision Dimensions

**Speed — How quickly do we need a solution?**
- Pre-trained APIs: days to weeks (mostly integration work)
- AutoML: weeks (time to collect/label data + training time)
- Custom model: months (data science work, architecture choices, training, evaluation)

**Effort — How much work is required?**
- Pre-trained APIs: low effort (call the API from our application code)
- AutoML: moderate effort (data collection, labeling, quality review)
- Custom model: high effort (data engineering, model architecture, training infrastructure, evaluation, monitoring)

**Differentiation — How unique is the competitive advantage?**
- Pre-trained APIs: zero differentiation (any company can call the same Vision API)
- AutoML: moderate differentiation (our specific training data produces a model tuned to our domain)
- Custom model: high differentiation (proprietary model = proprietary capability others cannot replicate)

**Required Expertise — Who needs to do the work?**
- Pre-trained APIs: any software developer (no ML knowledge required)
- AutoML: domain expert who understands the problem + basic data skills
- Custom model: ML engineers, data scientists, and data engineers

#### The Decision Spectrum
Visualize this as a spectrum. Moving from left to right:

```
Fast + Easy + Less unique ←————————————————→ Slow + Hard + More unique

[Pre-trained APIs]   [AutoML on Vertex AI]   [Custom Models on Vertex AI]
     Days                   Weeks                    Months
  Any developer          Domain expert             ML team required
 Zero differentiation   Some differentiation     High differentiation
```

The right choice depends entirely on our specific situation. Neither end of the spectrum is universally "better."

> **Key Point:** Most organizations use all three tiers simultaneously — pre-trained APIs for standard tasks, AutoML for domain-specific problems, and custom models for their core competitive capabilities.

### 3.2.b — The Three Tiers of Google Cloud AI/ML Solutions

#### Tier 1: Pre-Trained APIs
Google has trained massive ML models on enormous datasets (images, text, speech, video from across the internet and its own services). These pre-trained models are exposed as simple **API calls** — we send data to the API, it sends back a prediction.

**We provide:** our data (an image, a block of text, an audio file)
**Google provides:** the model, the training data, the infrastructure, the maintenance
**We receive:** a prediction or result (labels, transcription, translation, sentiment)

**Best fit:** when the general capability Google trained for matches our use case well enough. Vision API recognizes cats — if we need a general "what is in this image" capability, that's fine. If we need to distinguish between our company's 50 specific widget models, we need AutoML or custom.

**What we do NOT need:** training data, ML expertise, model training, model hosting

#### Tier 2: AutoML on Vertex AI
**AutoML** lets us train a custom model using our own labeled data, without writing any ML code. We provide the data; Google's automated ML system handles model selection, training, and optimization.

**We provide:** labeled training data specific to our domain
**Google provides:** the AutoML training platform, neural architecture search, training infrastructure, model hosting
**We receive:** a custom model tuned to our specific data and problem

**Best fit:** when pre-trained APIs don't know our domain well enough. Google's Vision API knows what a "dog" is — it doesn't know what "Widget Model XR-7 with Component Defect Type B" looks like. We train AutoML on our own labeled images of defective and non-defective widgets, and now we have a model that does.

**What we do NOT need:** ML engineering expertise, model architecture knowledge, training infrastructure

#### Tier 3: Custom Model Building with Vertex AI
**Custom model development** gives ML engineers and data scientists full control to build models from the ground up using frameworks like TensorFlow, PyTorch, and scikit-learn. Vertex AI provides the managed infrastructure so they can focus on the ML work rather than server management.

**We provide:** ML engineering expertise, proprietary data, model architecture decisions, training runs, evaluation
**Google provides:** managed training infrastructure, distributed training, hyperparameter tuning, model serving, monitoring
**We receive:** a fully proprietary model with maximum performance for our specific problem

**Best fit:** when we have a unique, complex problem where maximum accuracy creates direct competitive advantage, and we have the ML talent to pursue it.
